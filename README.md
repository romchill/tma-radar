# TMA Lead Radar

Ищет в Telegram людей, которым нужен Mini App, и складывает их в твоё приложение
как карточки клиентов.

Читает публичные каналы → ключевики отсеивают лишнее → оставшееся оценивается →
лучшие лиды дня попадают в ленту, горячие прилетают пушем в бота.

**Писать людям система не будет.** Всё до момента «нажать отправить» делается
за тебя, отправка — твоими руками. Массовая автоотправка = бан по правилам Telegram.

---

## Что нужно и сколько стоит

| Что | Нужно ли | Цена |
|---|---|---|
| Бот в Telegram (@BotFather) | да | бесплатно |
| Твой user id (@userinfobot) | да | бесплатно |
| Сбор из публичных каналов | работает сразу | бесплатно |
| Оценка по ключевым словам | работает сразу | бесплатно |
| Хостинг, домен, VPS | **не нужны** | — |
| Номер телефона, сим-карта | **не нужны** | — |
| `TG_API_ID` с my.telegram.org | только для чтения закрытых чатов | бесплатно, но часто недоступно |
| Ключ Anthropic | только для умной оценки и черновиков | ~0.2–0.3 ¢ за штуку, нужна карта |

Ключа Anthropic нет → система работает: оценка идёт по весу сработавших
ключевиков. Шумнее, потому что по одним словам не отличить заказчика от такого же
исполнителя, но лента наполняется. Черновики сообщений в этом режиме недоступны.
Вставишь ключ в `.env` позже — режим переключится сам.

## Как устроено

```
   публичные каналы (t.me/s/...) ──► worker
                                       │  channels + scorer + bot
                                       ▼
                                      db (postgres)
                                       │
                                       ▼
                                      api ──► мини-апп
                                       │
                                   tunnel (по надобности) ──► публичный https
```

Три контейнера. WSL отдано 3 ГБ на всё, и рядом постоянно крутится promt-shop
(~620 МБ), поэтому channels, scorer и bot — обычные asyncio-задачи в одном
процессе под присмотром: падение одной не роняет остальные.

| Решение | Почему так |
|---|---|
| Каналы читаются через `t.me/s/<имя>` | Telegram отдаёт их обычной веб-страницей — ни аккаунта, ни ключей, ни номера |
| Ключевики до модели | отсеивают почти всё, экономят и деньги, и время |
| Очередь — таблица `raw_messages` | хватает `FOR UPDATE SKIP LOCKED`, минус контейнер |
| Нет Caddy | порт 80 занят promt-shop, домена нет — статику раздаёт сам api |
| Наружу торчит только `127.0.0.1:8000` | из интернета машина недоступна |
| Адрес мини-аппа в базе, не в `.env` | у бесплатного туннеля он меняется каждый час |

### Чего так не собрать

Группы и чаты, где люди переписываются. У групп веб-версии нет — туда нужен
аккаунт. Каналы с вакансиями и заказами при этом читаются полностью, а там
часто лежат готовые ТЗ с бюджетом.

Если однажды заработает my.telegram.org — впиши `TG_API_ID` и `TG_API_HASH`
в `.env`, и юзербот подключится сам: код для него написан и на месте.

## Запуск

### 1. Получить два значения

| Что | Где |
|---|---|
| `BOT_TOKEN` | напиши [@BotFather](https://t.me/BotFather), команда `/newbot`, скопируй токен |
| `ADMIN_IDS` | напиши [@userinfobot](https://t.me/userinfobot), он пришлёт число |

### 2. Вписать их в `.env`

Файл уже создан, пароль базы сгенерирован. Заполни две пустые строки, остальное
не трогай.

### 3. Собрать мини-апп

```bash
cd webapp && npm ci && npm run build
```

### 4. Поднять

```bash
docker compose up -d
```

```bash
docker compose logs -f worker
```

### 5. Добавить каналы

Напиши боту:

```
/add @название_канала
```

Бот сразу проверит, читается ли канал, и скажет, сколько постов видит. Если это
группа или закрытый канал — честно ответит, что не выходит.

Ещё команды: `/list` — что собирается и сколько лидов дал, `/del @канал` — убрать.

Где искать каналы: поиск в Telegram по словам «вакансии разработка», «заказы
фриланс», «работа telegram», плюс каталоги вроде tgstat.

## Как открыть мини-апп

Telegram открывает приложения только по `https`, а домена нет — адрес даёт
временный туннель.

```bash
docker compose --profile tunnel up -d tunnel
```

Дальше ничего делать не нужно: туннель записывает выданный адрес в общий том,
бот подхватывает его за 20 секунд, обновляет кнопку «📡 Радар» и пишет тебе,
что адрес сменился. Команда `/url` осталась на случай, если захочется задать
адрес вручную.

Адрес меняется при каждом переподключении туннеля — это нормально и обрабатывается
само.

**Почему localhost.run, а не Pinggy.** Pinggy на бесплатном тарифе показывает
страницу «Caution — served through pinggy.io». Вебвью Telegram на ней спотыкается:
жмёшь «Enter site» и получаешь белый экран вместо приложения. У localhost.run
такой страницы нет — проверено с User-Agent Chrome, Telegram Android и iPhone.
Cloudflare Tunnel был бы стабильнее обоих, но на этой сети не поднимается:
порт 7844 закрыт и по UDP, и по TCP.

Сбор лидов и пуши в бота работают **без туннеля** — он нужен только чтобы
открыть само приложение.

Хочешь постоянный адрес вместо меняющегося — на localhost.run есть бесплатный
вариант с регистрацией и своим ssh-ключом: localhost.run/docs/forever-free

## Дневной лимит

`DAILY_LEAD_CAP` (по умолчанию 15) — сколько лучших лидов за сутки показывать
в ленте.

Оценивается всё, что прошло ключевики, а в ленту идёт топ-15 по баллам. Придёт
лид сильнее самого слабого из сегодняшних — вытеснит его и займёт место. Лиды,
которые ты уже начал вести («написал» и дальше), не вытесняются никогда.

Меняется в приложении: Настройки → Пороги. `0` отключает лимит.

## Калибровка

1. Вкладка «Мусор» в ленте — что зря отсеялось.
2. Настройки → Ключевики → «Песочница»: вставь реальный пост и посмотри,
   поймал бы его радар.
3. Аналитика → «Ключевики, которые приносят лидов»: чего там нет — тащит только
   шум, можно выключать.
4. Настройки → Промпты — правится, когда появится ключ Anthropic.

## Ограничения

- **Ноутбук должен быть включён.** Хостинга нет: радар читает каналы, только пока
  работает машина.
- **Адрес приложения живёт час.** Плата за отсутствие домена.
- **Только каналы, не группы.** Живые обсуждения без аккаунта недоступны.
- **Без ключа модели лента шумная.** Ключевики не понимают смысл.
- Память: контейнеры ограничены суммарно ~1 ГБ, чтобы не мешать promt-shop.

## Проверка, что всё живо

```bash
docker compose run --rm --no-deps api python -m app.scripts.e2e_channels
```

Прогоняет цепочку целиком на настоящей базе — канал, очередь, скоринг, лид —
и убирает тестовые данные за собой.

## Разработка

```bash
cd webapp && npm install && npm run dev
```

Vite поднимется на `127.0.0.1:5173` и проксирует `/api` на `127.0.0.1:8000`.
Вне Telegram подписи входа нет, поэтому создай `webapp/.env.local`:

```
VITE_DEV_USER_ID=твой_telegram_id
```

и поставь `DEV_MODE=true` в `.env`. **Удали `.env.local` перед `npm run build`** —
Vite запекает эти значения в готовую сборку. С `DEV_MODE=true` также открывается
документация API на `/api/docs`.
